## [Unreleased]

### Added

- **Web Search tool (Phase 0 — alignment)**: laid the groundwork for a new `search_web_search` LLM tool backed by the Google Custom Search JSON API. Added Rust dependencies (`async-trait`, `sys-locale`, `sha2`, `tauri-plugin-opener`, dev-dependency `wiremock`), registered the `tauri-plugin-opener` plugin scoped to `http://*` / `https://*`, and recorded the tool as _planned_ in `docs/tools-and-agent-integration.md`. Full feature spec, codebase investigation, mockups, and TDD phase plan live under `docs/tools/web_search/`. No tool code yet; subsequent phases land the `SearchProvider` trait, `WebSearchTool` implementation, DB-backed credentials, per-workspace domain policy, result cache, Tauri commands, Settings UI, and `ToolCallMessage` renderer extraction.
- **Web Search tool (Phase 2 — provider trait and mock)**: introduced the `SearchProvider` async trait, the `SearchRequest` / `RawResult` DTOs, and the `SearchProviderError` enum (`RateLimited`, `Unauthorized`, `Upstream`, `Network`) under `web_search/provider/mod.rs`. Added a `#[cfg(test)]`-only `MockProvider` with canned-result support, FIFO-scripted responses (`enqueue(MockResponse::*)`), and observed-request recording for end-to-end tool tests. Covered by 7 async unit tests in `web_search/tests/provider_mock_tests.rs`. No production impact yet — the trait is the seam `WebSearchTool::execute` consumes in Phase 3 and `GoogleProvider` implements in Phase 4.
- **Web Search tool (Phase 1 — types and argument validation)**: introduced `src-tauri/src/infrastructure/tools/search/web_search/` with `types.rs` (`WebSearchArgs`, `WebSearchResult`, `WebSearchOutput`, `PROVIDER_GOOGLE_CUSTOM_SEARCH`) and a pure `WebSearchArgs::into_validated` that trims the query, rejects empty/oversized queries, clamps `num_results` to `[1, MAX_WEB_SEARCH_LIMIT]`, normalizes optional `language`/`site` strings, and honors `deny_unknown_fields`. Added five constants to `infrastructure/tools/constants.rs` (`MAX_WEB_SEARCH_LIMIT`, `MAX_WEB_SEARCH_QUERY_LEN`, `ENV_WEB_SEARCH_ENABLED`, `ENV_WEB_SEARCH_API_KEY`, `ENV_WEB_SEARCH_CX`). Covered by 12 unit tests in `web_search/tests/args_tests.rs` exercising defaults, trimming, multibyte length counting, empty-input rejection, clamp behavior (both directions), optional-string normalization, and unknown-field rejection. No HTTP, DB, or provider wiring yet — `WebSearchTool::execute` lands in Phase 3.
- Initial project structure with Tauri v2 + Svelte + TypeScript
- Rust backend with modular architecture (commands, agents, utils)
- SvelteKit frontend with static adapter for Tauri integration
- Design system with CSS custom properties for theming
- Dark mode support by default
- Global styles with Inter and JetBrains Mono fonts
- ESLint and Prettier configuration for frontend code quality
- Clippy configuration for Rust code quality
- Basic Tauri commands (`health_check`, `get_app_info`)
- AI agent type definitions
- A mandatory code-quality guideline set under `docs/quality/guidelines/` for Rust backend, TypeScript, Svelte, configuration, and scripts, with `AGENTS.md` enforcing the required reading order.

### Changed

- Unified NLP LLM integration with the shared provider-agnostic `llm` layer via `NlpLlmGateway` and config-driven model/provider/API-key resolution.
- Migrated NLP components (`IntentClassifier`, `MultiIntentDetector`, `ContextManager`) from legacy Claude-specific usage to shared gateway abstractions with deterministic fallback behavior on LLM failures.
- Rewired NLP app state/bootstrap initialization to use config/context databases and removed hardcoded dev API-key initialization paths from runtime wiring.
- Removed legacy Claude module files (`src-tauri/src/ai/claude.rs`, `src-tauri/src/ai/mod.rs`) and `pub mod ai` export from backend crate root.
- **Enabled LLM tools by default**: The orchestrated conversation runner with tool support is now the default, restoring workspace file listing and other tool functionality without requiring environment variable configuration.

### Fixed

- **Context compaction "N -> N tokens" no-op notice**: The chat no longer surfaces a "Context updated — 967 -> 967 tokens" system message on every subtask transition. Root cause was four compounding backend defects in `src-tauri/src/infrastructure/agent/runtime/context.rs` and its call site in `src-tauri/src/application/agent/execution/context_phase.rs`: (1) `estimate_context_tokens` relied on `ChatMessage::as_text`, which ignored `MessageContent::Blocks`, `tool_calls` arguments, and `tool_result.output` JSON — a tool-heavy conversation reported ~10 tokens/message when real size was thousands; (2) `apply_context_policy_v2` unconditionally returned `Some(CompactionDetails)` even when the packed context was identical in size, firing the `ContextCompacted` event with a zero delta; (3) `force_pack: subtask_changed` triggered packing on every subtask transition regardless of context size, including tiny contexts where packing is a semantic no-op; (4) the UX conflated *compaction* (reduction) and *subtask-transition repack* (reorganization) under a single event shape that implied reduction. Introduced `ContextPackOutcome { Compacted, Reorganized, Unchanged }` and `classify_outcome` to distinguish meaningful compaction from benign reorganization using `MIN_SAVINGS_TOKENS` (200) + `MIN_SAVINGS_RATIO` (5%) thresholds; added a `TINY_CONTEXT_RATIO` (10%) early-return that skips forced packing on near-empty contexts; rewrote `estimate_context_tokens` with `estimate_message_tokens`, `estimate_content_tokens`, `estimate_tool_call_tokens`, `estimate_tool_result_tokens`, and `estimate_json_tokens` helpers so tool JSON, Blocks text, and image framing (`IMAGE_TOKEN_COST` = 1200) are all counted; extracted `record_compaction` + `should_emit_compaction_event` in `context_phase.rs` to gate emission on `outcome == Compacted`, real token savings, and token-limit triggering — repack events are still recorded on `RuntimeTraceType::ContextPolicyEvaluated` traces and logged at `debug!` but no longer surface to the user. Frontend defense-in-depth: `buildContextNoticeContent` now omits the `-> tokens` tail when `beforeTokens === afterTokens`, `parseSystemNoticeFromMessage` tolerates missing tails so the new emission format round-trips, `SystemNoticeMessage.svelte` hides the metrics strip for equal-token historical DB rows, and `handleContextCompacted` early-returns on zero-delta events. Added 11 new tests in `context.rs` (`test_estimate_counts_tool_call_arguments`, `test_estimate_counts_tool_result_output`, `test_estimate_counts_blocks_content`, `test_estimate_image_block_has_fixed_cost`, `test_apply_policy_v2_skips_tiny_forced_context`, `test_apply_policy_v2_classifies_unchanged_correctly`, `test_classify_outcome_reorganized_when_insufficient_savings`, `test_classify_outcome_compacted_when_real_savings`, `test_maybe_compact_context_populates_outcome`) and 5 in `context_phase.rs` covering the emission predicate, plus 2 in `systemNotices.test.ts` covering zero-delta suppression and tail-less parse.
- **CSS integrity across the UI**: Eliminated undefined CSS variables (`--color-text-quaternary`, `--color-error-200/600/subtle`, `--color-success-200/600`, `--color-warning-200/600/subtle`, `--color-border/-default/-hover/-muted`, `--color-bg-hover`, `--color-surface-disabled`, `--color-surface-primary`, `--color-primary-glow-strong`, `--color-accent-cyan`, `--color-accent-rose`, `--text-tertiary`) across `StatusBadge`, `Input`, `Select`, `ArtifactPanel`, `ArtifactCard`, `AgentConfig`, `AgentPanelHeader`, `AppShell`, `MentionMenu`, `MarkdownPreview`, `CommandPalette`, `ConversationSidebar`, `ConversationItem`, `SystemNoticeMessage`, and `ThreadItem` by remapping each reference to the correct token in `design-system.css`. Added the missing `--space-4-5` and `--space-7-5` spacing tokens that `ThinkingMessage`, `ToolCallMessage`, and `ToolCallItem` expected. Removed two empty rulesets (`.hasUnread`, `.streaming`) in `ThreadItem.module.css` that previously triggered Vite's CSS module loader failure mode. Replaced the invalid jQuery-style selector `.artifact-card:has(.artifact-language:contains('Terminal'))` in `ArtifactCard.svelte` with a Svelte state class (`class:terminal={type === 'terminal'}`) + `.artifact-card.terminal`; the previous selector was rejected by Svelte's CSS parser and was the root cause of the cascading `[vite-plugin-svelte:load] failed to load virtual css module` warnings for `+page.svelte`, `AppShell.svelte`, `AgentPanel.svelte`, `SessionHistory.svelte`, and `AgentConfig.svelte`. To prevent this recurring class of bug, added `src-ui/src/lib/styles/css-integrity.test.ts` which fails the test suite when any `var(--token)` without a fallback references an undefined variable, any CSS ruleset has a whitespace-only body, or any selector uses a jQuery-only pseudo-class (`:contains`, `:parent`, `:eq`, `:gt`, `:lt`), and configured `vite.config.ts` with `server.warmup.clientFiles: ['./src/**/*.svelte']` so Svelte's CSS parser runs against every component at dev-server start — invalid selectors now surface as a first-class error in the dev log instead of hiding behind a cascade of virtual-CSS load warnings. Wired the test and the warmup into the CSS Verification Checklist in `RULES.md`.

- **Frontend dev server startup**: Restored modern SvelteKit dependency versions in `src-ui` so `vite.config.ts` can resolve `@sveltejs/kit/vite` again during `npm run dev`.
- **LLM tools regression**: Tools like workspace file listing were disabled after the refactor due to environment flag requirements. Now tools work out-of-the-box with graceful fallback to legacy runner if needed.
- **Agent session runtime persistence**: Thread-linked agent sessions now rehydrate persisted files touched and tool-call history when a thread is reopened, switched back to, or restored after restarting the app. Tool-call IPC payloads now include stable camelCase fields and persisted timestamps.
- **PPTX blank slides**: `pptx_finalize` now renders slide title and body content (text boxes, bullet lists, numbered lists) into generated `.pptx` files instead of creating empty slides, and regression tests now assert slide XML contains authored text.
- **Agent command spawning**: Added a backend spawn service with policy checks, bounded concurrency, cancellation handling, and runtime trace telemetry so command failures stay inside the tool/runtime boundary instead of crashing the app.
- **Agent messages replaced on the frontend**: Subtask results, the "continuing with next subtask..." divider, and the final summary all shared a single session-wide message id when the backend emitted `streaming_content` without a `messageId`, so each new message overwrote the previous one in the chat store. Introduced a phase-aware id scheme (`stream-{phase}-{session}-{task}-{subtask}-s{step}`) built by a new `streaming_message_id` helper, made `emit_streaming_content` / `emit_streaming_message` require an explicit id at compile time, and added a defensive frontend fallback that generates a unique orphan id per event with a logged warning if a missing id ever slips through. Covered by new unit and integration tests in `message_ids.rs`, `termination.rs`, and `streamingEvents.test.ts`. See `docs/features/agent-streaming-message-ids.md`.
- **Silent provider-removal failures**: `configStore.removeProvider` now captures backend errors into `state.error` before rethrowing, and `+page.svelte` forwards that error into the existing status-bar surface so users see a visible message instead of the Remove button appearing to do nothing. Removed the dead inline fallback in `SettingsModal.svelte` — the callsite always supplies `onremoveprovider`. Covered by new tests in `configStore.test.ts` and an updated handler assertion in `SettingsModal.test.ts`.
- **Stale validation error in `CustomProviderModal`**: A failed submit (e.g. "Invalid URL format") previously remained on screen while the user typed into the field that would fix it. Input change handlers for provider name, provider id, base URL, and API-type radios now clear the inline error on edit, so the banner disappears as soon as the user starts correcting the form. Covered by new tests in `CustomProviderModal.test.ts`.
- **`ThreadIndicator` didn't surface resolved state**: the inline thread-badge rendered on messages ignored `thread.metadata.resolved` entirely, while the sidebar `ThreadItem` already used a check-circle icon for resolved threads — so users had inconsistent visual signals about thread lifecycle. `ThreadIndicator.svelte` now takes an optional `resolved` prop, renders a check-circle icon and muted `.resolved` styling when set, and exposes a distinct `aria-label`. `ChatMessagesList.svelte` wires the flag through via a new `isThreadResolved(id)` helper that reads from the existing `threads` prop. Covered by new tests in `ThreadIndicator.test.ts`.
- **`STREAM_END` final scroll was unreachable**: `handleStreamingEnd` in `scrollController.ts` called `sendEvent('STREAM_END')` before reading `context.autoScrollEnabled`, but the state-change listener synchronously flipped that flag to `false` as soon as the state machine transitioned to `idle`, so the guarded catch-up scroll at stream end never ran. Long `isComplete.content` payloads could leave the viewport a few lines short of the true bottom. `handleStreamingEnd` now snapshots `autoScrollEnabled` before dispatching the event, and the dead mirror-branch for `STREAM_END` inside `handleStateTransition` was removed. Covered by new tests in `scrollController.test.ts`.

- **ConfirmDialog `warning` variant silently rendered as `primary`**: the public `variant` prop advertised `'primary' | 'danger' | 'warning'`, but `ConfirmDialog.svelte` aliased `warning` back to `primary` before forwarding to `Button`, which had no `warning` style at all. Warning confirmations therefore had no visual distinction from neutral ones. `Button` now exposes a dedicated `warning` variant wired to `--color-warning` / `--color-warning-light` design tokens (including reduced-motion and expressive-hover parity), and `ConfirmDialog` forwards `variant` unchanged. Updated the three variant tests in `ConfirmDialog.test.ts` to assert the confirm button actually carries the corresponding `primary` / `danger` / `warning` class so this can't silently regress.

- **`IntentIndicator` swallowed backend classification errors**: when `classifyInput` in `chat.ts` caught a failure from the backend NLP classifier, it stored the message into `$nlpState.error`, but `ChatInput.svelte` discarded that field entirely — the indicator just vanished, leaving the user with zero feedback. `IntentIndicator.svelte` now accepts an optional `error` prop; when set (and not loading) it renders a dedicated error badge with an alert-circle icon, the label `Intent unavailable`, `aria-label="Intent detection unavailable"` for assistive tech, and the raw error message exposed via `title` for sighted users. Confidence display is suppressed in the error state, and loading wins when both are set. `ChatInput.svelte` now forwards `$nlpState.error` (only when backend NLP is enabled) and keeps the indicator mounted when the only signal is an error. Covered by 7 new tests in `IntentIndicator.test.ts`.

- **Silent `configStore` API failures**: four call sites swallowed or re-threw backend errors without routing them into `state.error`, leaving the status bar blind to provider-setup failures. `saveProvider`, `setOperationDefault`, and both failure paths of `fetchModels` (rejected promise *and* `success: false` result) now capture the error message into `state.error` before re-throwing, following the pattern established by `removeProvider`. `initialize` now aggregates per-provider `apiGetModels` failures (previously only `log.warn`'d) into a human-readable `state.error` like `"Failed to load models for 2 provider(s): Provider 1: Network down; Provider 2: Network down"` so startup-time credential/network issues surface in the UI instead of silently leaving providers with zero models. Covered by 6 new tests in `configStore.test.ts`.

- **Ghost thread selection when thread ID no longer exists**: when `chatStore.selectThread(id)` was called with an ID that wasn't present in the loaded `threads` array (stale agent-session reference, race after a delete, future URL routing), the store still transitioned `messagesLoading` through `'loading'` → `'success'`, wired the stale `threadId` into `ChatArea`'s input box, and let the user type into a non-existent thread with no error feedback. `selectThread` now short-circuits when `threadsLoading === 'success'` and the requested ID is not in `threads`: it clears `selectedThreadId`, clears the active agent session, resets `messagesLoading` to `'idle'`, and sets `state.error = 'Thread no longer exists'` so the existing status-bar surface shows a dismissible notice. The pre-load phase is tolerated (`'loading'` / `'idle'`) to avoid false positives during conversation switching. Covered by 2 new tests in `chat.test.ts`.
