### Added

- **PDF styling — per-page `theme_override` on `pdf_add_page`**: individual pages can now carry their own `theme_override` with the same shape as the document-level `theme` on `pdf_start`. When set, it takes effect from that page onward and persists until another `theme_override` fires; pages without an override that follow an overridden page automatically reset to the document theme — the adapter inserts a synthetic reset marker at the boundary so styling does not bleed forward. Only body-level fields are honoured (`typography`, `palette`, `spacing`, `page_defaults.margin_mm`); `decorations` and `fonts.*` remain document-wide because the decorator runs a single post-layout pass and the font cache is built once at document construction. This limitation is documented in the tool description, in `docs/features/pdf-styling.md`, and called out in the `DOCUMENT GENERATION` system-prompt block so the LLM picks the right knob for the task. Implementation: a new `Block::ThemeSwitch(ThemePatch)` variant in `src-tauri/src/core/documents/pdf/block.rs` carries the patch through the block stream; `build_document` in `src-tauri/src/application/tools/pdf/finalize.rs` emits it before each overridden page and follows it with an empty-patch reset after an overridden page's blocks; the renderer handles it in `layout_sections` by calling a new `LayoutEngine::set_params` with freshly-built `LayoutParams` for the merged `(base_theme + patch)` — cursor and page state are preserved, only the layout knobs swap. `decode_theme_override` at the tool boundary runs the same per-field validation as `pdf_start` and surfaces failures as `ToolError::invalid_args` naming the dotted JSON path. The existing `layout_sections` signature was extended with a small `RenderThemeCtx` struct bundling `doc`, `base_theme`, and page dimensions so the `ThemeSwitch` arm can rebuild params without threading four extra args through the function. 7 new tests: 4 at the tool boundary (`decode_theme_override` accepts missing / null / valid; rejects out-of-range naming the offending field), 2 `build_document` unit tests (inserts exactly one override + one reset when the middle page of three is overridden; emits zero `ThemeSwitch` blocks when no page has an override — locks the backwards-compatible path), and 1 end-to-end `per_page_theme_override_changes_rendered_output` integration test in `write.rs` that renders baseline vs. overridden two-page drafts and asserts the output bytes differ. Full lib test suite: 1985 passing.
- **PDF generation — cover pages and image sizing on `pdf_add_page`**: `content` now accepts two new shapes. `{type: "cover", title, subtitle?, author?, date?}` renders a dedicated page with everything centred horizontally and vertically inside the usable area, forces a page break before and after, and records the title on the PDF outline so bookmarks stay intact. Header/footer suppression on the cover is handled by the existing `decorations.suppress_on_first_page` flag. Image content now accepts optional `width_mm`, `height_mm`, and `fit` (`contain` default — preserves aspect, letterboxes; `stretch` — uses both dimensions literally). When only one dimension is set, the other is derived from pixel aspect ratio; when neither is set, the image fits the usable page width as before. Backing types: new `CoverBlock` and `ImageFit` in `src-tauri/src/core/documents/pdf/block.rs` plus an `ImageBlock::resolved_size_mm(aspect, usable_width_mm)` helper that does the four-way sizing decision in pure model code (unit-tested). New renderer branch `emit_cover_page` in `printpdf_renderer.rs` lays out the cover using existing `measure_with_face` and `LayoutEngine` primitives — no font-metric rewrites. The section loop in `layout_sections` skips the auto-generated heading when a section's first block is a cover so the document title does not appear above it. `layout.rs` ordering unchanged; `HALF` / `FALLBACK_IMAGE_DPI` / `COVER_META_GAP_MULTIPLIER` moved to named consts so the sweep test (no numeric literals in render path) still passes. 9 new unit tests across `block.rs` (`resolved_size_mm` covering all four size-input combinations including Contain vs Stretch) and `adapter.rs` (cover conversion, whitespace trimming, blank-title rejection); 3 new conversion tests in `add_page.rs` (image sizing preserved, cover conversion). New end-to-end integration test `cover_page_followed_by_markdown_renders_multi_page_pdf` in `write.rs` renders a real two-page PDF and parses it with `lopdf` to confirm the cover + markdown sequence produces at least two pages. Per-page theme overrides are explicitly deferred to Phase 3 — documented as a non-goal in `docs/features/pdf-styling.md`.
- **PDF styling — LLM-tunable theme at `pdf_start`**: the PDF generation tool now accepts an optional `theme` object that overlays the bundled report theme. Every field is optional; the LLM supplies only what the user asked to change and the rest inherits. Supported sections: `typography` (`body_font_size_pt`, `heading_font_size_pt`, `line_leading`), `palette` (8 RGB slots covering body, headings, code, callouts, tables), `spacing` (`block_gap`, `list_indent_mm`, `block_padding_mm`, `table_cell_padding_mm`), `page_defaults.margin_mm`, `decorations` (`header`/`footer` templates with the existing `{title}/{page}/{total_pages}/{section}` tokens — pass explicit `null` to drop a strip — plus `suppress_on_first_page`, `font_size_pt`, `margin_mm`), and `fonts` (names restricted to the bundled allow-list: `LiberationSans-Regular.ttf`, `LiberationSans-Bold.ttf`, `LiberationSans-Italic.ttf`, `LiberationMono-Regular.ttf`, `DejaVuSans.ttf`). The patch type lives in `src-tauri/src/core/documents/pdf/theme_patch.rs`; `ThemePatch::validate` enforces per-field ranges (RGB `[0,1]`, body font `[6,72]`, heading font `[8,96]`, leading `[1.0,2.5]`, margin `[5,80]` mm, etc.) and surfaces failures as `ToolError::invalid_args` messages that name the offending JSON path so the LLM can self-correct on the next step. `pdf_start` decodes the raw JSON via `decode_theme_patch` and stores the patch on `PdfDraft.theme_patch`; the render seam in `write.rs` now calls the new `theme_for_draft(&draft)` helper in `theme_loader.rs`, which merges the patch onto the bundled theme. The `DOCUMENT GENERATION` block in `src-tauri/src/infrastructure/agent/registry.rs` teaches the LLM the new surface with an end-to-end example. Backwards-compatible — absent `theme` returns the bundled theme byte-for-byte (locked by the new `theme_for_draft_without_patch_matches_bundled` test), and an end-to-end test `theme_patch_on_draft_changes_rendered_output` proves the patch actually propagates through `printpdf`. 20 new unit tests in `theme_patch.rs`, 5 in `start.rs`, 3 in `theme_loader.rs`, 1 in `draft_store.rs`, plus the end-to-end test in `write.rs`. Feature contract: `docs/features/pdf-styling.md`.

- **Context compaction "N -> N tokens" no-op notice**: The chat no longer surfaces a "Context updated — 967 -> 967 tokens" system message on every subtask transition. Root cause was four compounding backend defects in `src-tauri/src/infrastructure/agent/runtime/context.rs` and its call site in `src-tauri/src/application/agent/execution/context_phase.rs`: (1) `estimate_context_tokens` relied on `ChatMessage::as_text`, which ignored `MessageContent::Blocks`, `tool_calls` arguments, and `tool_result.output` JSON — a tool-heavy conversation reported ~10 tokens/message when real size was thousands; (2) `apply_context_policy_v2` unconditionally returned `Some(CompactionDetails)` even when the packed context was identical in size, firing the `ContextCompacted` event with a zero delta; (3) `force_pack: subtask_changed` triggered packing on every subtask transition regardless of context size, including tiny contexts where packing is a semantic no-op; (4) the UX conflated *compaction* (reduction) and *subtask-transition repack* (reorganization) under a single event shape that implied reduction. Introduced `ContextPackOutcome { Compacted, Reorganized, Unchanged }` and `classify_outcome` to distinguish meaningful compaction from benign reorganization using `MIN_SAVINGS_TOKENS` (200) + `MIN_SAVINGS_RATIO` (5%) thresholds; added a `TINY_CONTEXT_RATIO` (10%) early-return that skips forced packing on near-empty contexts; rewrote `estimate_context_tokens` with `estimate_message_tokens`, `estimate_content_tokens`, `estimate_tool_call_tokens`, `estimate_tool_result_tokens`, and `estimate_json_tokens` helpers so tool JSON, Blocks text, and image framing (`IMAGE_TOKEN_COST` = 1200) are all counted; extracted `record_compaction` + `should_emit_compaction_event` in `context_phase.rs` to gate emission on `outcome == Compacted`, real token savings, and token-limit triggering — repack events are still recorded on `RuntimeTraceType::ContextPolicyEvaluated` traces and logged at `debug!` but no longer surface to the user. Frontend defense-in-depth: `buildContextNoticeContent` now omits the `-> tokens` tail when `beforeTokens === afterTokens`, `parseSystemNoticeFromMessage` tolerates missing tails so the new emission format round-trips, `SystemNoticeMessage.svelte` hides the metrics strip for equal-token historical DB rows, and `handleContextCompacted` early-returns on zero-delta events. - **Silent `configStore` API failures**: four call sites swallowed or re-threw backend errors without routing them into `state.error`, leaving the status bar blind to provider-setup failures. `saveProvider`, `setOperationDefault`, and both failure paths of `fetchModels` (rejected promise *and* `success: false` result) now capture the error message into `state.error` before re-throwing, following the pattern established by `removeProvider`. `initialize` now aggregates per-provider `apiGetModels` failures (previously only `log.warn`'d) into a human-readable `state.error` like `"Failed to load models for 2 provider(s): Provider 1: Network down; Provider 2: Network down"` so startup-time credential/network issues surface in the UI instead of silently leaving providers with zero models. Covered by 6 new tests in `configStore.test.ts`.

- **Ghost thread selection when thread ID no longer exists**: when `chatStore.selectThread(id)` was called with an ID that wasn't present in the loaded `threads` array (stale agent-session reference, race after a delete, future URL routing), the store still transitioned `messagesLoading` through `'loading'` → `'success'`, wired the stale `threadId` into `ChatArea`'s input box, and let the user type into a non-existent thread with no error feedback. `selectThread` now short-circuits when `threadsLoading === 'success'` and the requested ID is not in `threads`: it clears `selectedThreadId`, clears the active agent session, resets `messagesLoading` to `'idle'`, and sets `state.error = 'Thread no longer exists'` so the existing status-bar surface shows a dismissible notice. The pre-load phase is tolerated (`'loading'` / `'idle'`) to avoid false positives during conversation switching. Covered by 2 new tests in `chat.test.ts`.
